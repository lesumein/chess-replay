# chess-replay

Chess.com에서 내가 놓친 장면을, "여기 뭔가 있다"는 신호 없이 3~5수 전부터 봇과 다시 두는 폰 웹앱.

## 시험할 것
- 퍼즐처럼 장면을 알려 주지 않고 실전처럼 다시 두게 하면, 실전에서 놓친 기회·큰 실수가 줄어드는가.
- 2주 동안 손이 가는가. 안 가면 접는다.
- 첫 관문: 폰에서 Stockfish로 한 판을 쓸 만한 시간 안에 분석할 수 있는가.

## 범위 (첫 버전)
- Chess.com 아이디만 입력. 로그인·서버 없음. 공개 API에서 **끝난 게임만** 가져온다.
- 폰에서 Stockfish(WASM, 싱글스레드)로 분석해 놓친 기회·큰 실수 장면을 찾는다. 저장은 localStorage/IndexedDB.
- 장면 3~5수 전부터 신호 없이 봇과 이어 두기, 수마다 시계. 아무것도 없는 가짜 장면도 섞는다.
- 끝나면 한 줄 결과만. 결제는 아직 붙이지 않음.

## 결과
- 분석 속도 재기 화면(`bench.html`): 아이디 → 최근 끝난 게임 고르기 → 깊이별로 한 판 분석 시간과 찾은 장면 표시.
- 이 컴퓨터(Playwright, Pixel 7 화면, 51수 블리츠 한 판): 깊이 10 0.6초, 12 1.6초, 16 14초, 20 134초.
  - 깊이 10~12에서도 짚어 둔 세 장면(14...Nxf3+, 23수 Bf7, 27...c5)을 모두 잡았다.
  - 23...Qa4(6수 메이트)는 깊이 20에서야 보인다. 얕으면 대신 Bf7(+5)을 내놓는다.
- 폰(안드로이드, Chrome 155, 2026-10-25, 같은 게임): 엔진 로드 0.4초.

  | 깊이 | 한 판 | 포지션당 평균 / 최대 | 장면 |
  |---|---|---|---|
  | 10 | 1.2초 | 12ms / 97ms | 7개 |
  | 12 | 3.1초 | 31ms / 157ms | 6개 |
  | 16 | 30초 | 291ms / 1.4초 | 6개 |
  | 20 | 289초 | 2.8초 / 16초 | 6개 (23수 최선이 Qa4로 바뀜) |

  - 첫 관문 통과: 깊이 12로 한 판 3초. "열 때마다 1~2판씩"이 충분히 된다.
  - 폰은 이 컴퓨터보다 약 2배 느리다.

## 동작 (첫 버전)
- 아이디 입력 → 끝난 게임을 최근 것부터 한 판씩 분석(깊이 12) → 찾은 장면만 깊이 16으로 다시 확인하고 하나씩 바로 저장. 장면이 없으면 첫 장면이 생기자마자 시작.
- 앱이 열려 있는 동안(화면이 보일 때) 다음 판을 계속 분석. 이번 달을 다 하면 지난 달로.
- 장면은 손해가 큰 것부터. 장면 2~4수 전(장면마다 다름) 포지션에서 시작하고, 장면 뒤로 2수 더 두면 끝.
  - 시작 전에 원래 게임의 앞 6반수를 빠르게 다시 보여 준다(탭하면 건너뛰기). 오래된 게임도 흐름이 떠오르게. 위에는 "3주 전 · 블리츠 · 진 판".
  - 4수 전에서 고정으로 시작하면 원래 길에서 벗어나 장면이 안 오는 일이 많았다(폰 사용 후기).
- 내가 원래 게임대로 두는 동안 상대도 원래 게임대로 둔다. 다른 길로 가면 봇이 받는다.
- 봇 세기: 원래 상대 레이팅. 후보 8개를 깊이 10으로 보고 레이팅이 낮을수록 점수 차를 덜 따져 고르며, 가끔 아무 수나 둔다(100점: 12%, 400점: 5%, 800점: 2%, 1600점 이상: 0). 첫 버전(25%/12%/5%)은 폰에서 너무 약했다.
- 시계(설정에서 고름): 앱 시계(기본, 내 수 하나에 20초꼴) 또는 원래 게임 시계(시작한 순간 원래 남아 있던 시간에서 시작하고, 내가 둘 때마다 그 게임의 수당 추가시간을 더한다. 시계 옆에 "+5초", 위에 "블리츠 5+5"). 원래 시간 기록이 없으면 앱 시계. 예전에 만든 장면은 앱을 열 때 기보를 다시 읽어 시계 정보를 채우고(엔진 없이), 시작 전 원래 수순이 없는 장면의 게임은 뒤에서 다시 분석해 새 방식으로 만든다(같은 자리 장면은 id가 같아 기록이 이어짐). 결과에 "이 수에 N초 · 원래 게임에선 M초"(원래는 기보의 %clk로 계산).
- 공유로 복기: Chess.com 앱에서 게임 '공유하기' → 이 앱(안드로이드 앱, 또는 홈 화면에 설치한 웹 앱). Chess.com 링크는 최근 6달 내 내 게임에서 찾고(공개 API에 게임 번호로 찾는 길이 없다), Lichess 링크는 Lichess 공개 API로 PGN을 받고, PGN은 그대로 읽는다. 남의 게임은 어느 쪽으로 둘지 고른다(쪽마다 장면 후보 수, Lichess 링크의 /white·/black을 앞세움). 설정의 '내 다른 아이디'(부계정·Lichess)가 든 기보는 묻지 않고 그쪽으로. 바로 분석해 손해가 큰 장면부터 둔다(다 두면 원래 순서로).
- 원래 게임과 비교: 시작한 판부터 같은 수만큼, 내 수마다 최선 대비 잃은 점수(깊이 12, 한 수 최대 10폰)를 원래 게임과 이번 판에서 각각 더해 "원래 대비 +3.1"처럼 보여 준다(상대·봇의 수는 빼고 내 판단만). 1폰 이상 차이면 "원래보다 잘 뒀어요/나빠졌어요", 안이면 "비슷해요". 홈에 "원래보다 나은 판" 비율.
- 다른 길로 가면 그 길에서 내가 놓친 기회·큰 실수 중 첫 번째를 알려 준다. 장면이 안 왔으니 원래 대비로 가린다: 1폰 이상 나으면 "다른 길로 더 잘 뒀어요"(잘 둔 것), 1폰 이상 나쁘면 "다른 길에서 흔들렸어요", 그 사이면 "다른 길로 갔어요"(회색, 셈에서 뺌 — 다른 길로 간 것 자체는 못 둔 게 아니다). 세트 결과의 큰 숫자는 "잘 둔 장면"(찾음·잘 넘김·다른 길로 더 잘 둠) / 셈에 든 장면. 세트 결과의 [홈으로] [한 세트 더]는 화면 아래에 붙어 있다.
- 판정: 장면에서 둔 수가 최선과 1.2폰 안이면 찾은 것. 결과는 한 줄 + 장면 포지션에 화살표(초록: 좋은 수, 빨강: 둔 수). 결과를 넘겨 볼 때 ◀ ▶ 바는 화면 아래에 떠 있고(가운데에 지금 수), 판 왼쪽/오른쪽 탭·옆으로 밀기·키보드 ← →로도 넘긴다. 결과 탭: 좋은 수·둔 수(시작한 판부터 장면까지 원래 흐름을 흐리게 앞에 붙이고, 장면 포지션에서 열림), 원래 vs 이번(작은 판 두 개를 같은 수 번호로 나란히 넘기고(판 위 숫자는 그 수까지 내 수가 잃은 점수의 합, 위에 "여기까지 원래 대비 · 이번 +N · 좋은 수 +M" — 이번은 마지막 수에서 결과의 원래 대비와 같다. 좋은 수 갈래는 장면 뒤 엔진 최선 수를 손실 0으로 센다. 최선 갈래(왼쪽 판에서 고름)는 시작한 판부터 양쪽 모두 엔진 최선(깊이 12, 상대 수도 엔진이라 원래와 다른 판) — 이 구간에서 얻을 수 있는 최대치. 표의 세 번째 줄은 고른 갈래(좋은 수/최선)를 따른다. 원래 게임에서 내 수가 0.5폰 이상 잃은 칸에는 그 자리의 최선 수("최선 Nxf3+")를 적는다(분기 전에 무엇을 뒀어야 했나). 같은 길로 온 수는 같은 평가를 써서 같은 수가 다르게 매겨지지 않게. 한 수 손실은 0.1폰 단위로 맞춰 합들이 정확히 맞게), 아래 표에 수마다 원래·이번·좋은 수 세 수순과 형세, 갈린 수 표시. 왼쪽 판은 원래와 좋은 수 중 골라 봄. 갈린 수를 둔 뒤에서 열림).
- 판·기물: cm-chessboard + 위키백과 표준 기물(직접 그린 판은 보기 어려워서 바꿈).
- 세트: 장면 5개가 한 세트. 홈 위쪽 카드에 오늘의 세트 진행(5칸), 연속으로 둔 날, '세트 시작/이어서 두기' 버튼, 준비된 장면·분석한 게임 수. 아래에 찾은 비율, 원래보다 나은 판, 연속 일수, 최근 장면(누르면 그 장면을 다시 둔다). 다섯 번째 장면 뒤에는 세트 결과(찾은 장면 고리, 원래 대비 합계, 장면별 결과, 한 세트 더). 아이디를 바꾸면 기록을 지운다.
- 두는 동안 화면에는 상대·시계·판, 이름 아래 잡은 기물과 점수 우위(+N, 폰 1·나이트/비숍 3·룩 5·퀸 9). 결과의 수순을 넘길 때도 따라 바뀐다.
- ◀ ▶(복기, 두는 동안 지난 수 보기)는 누르고 있으면 반복하며 점점 빨라진다(0.38초 뒤부터, 간격이 0.8배씩 줄어 최소 0.045초). 두는 동안 ◀ ▶로 지난 수를 되돌려 볼 수 있다(시계는 계속 간다, 새 수가 오면 지금 판으로). 결과의 '끝난 판'은 이번에 둔 수를 처음부터 넘겨 본다.
- 결과는 아래에서 올라오는 시트(판정, 한 줄, 원래 대비, 쓴 시간, [복기] [다음 장면]). 판은 위에 그대로 보이고 장면 포지션에 화살표. 복기를 누르면 시트가 내려가고 판 아래에 탭·수순·◀ ▶ 바가 나온다.
- 화면 톤: 기보 용지. 종이색 바탕에 먹색 글, 카드 그림자 대신 가는 줄. 대표색은 아이콘의 짙은 녹색 하나(버튼·작은 제목·지금 수), 결과 색은 그보다 밝은 초록과 벽돌색. 제목·판정·큰 숫자는 바탕체(Gowun Batang), 나머지는 Pretendard. 홈의 세트는 1~5 줄이 있는 기록지로, 둔 줄에 결과가 채워지고 앞으로 올 장면은 빈칸(신호 없음). 기본 시스템 글꼴과 둥근 카드·그림자 위주의 흔한 모습이 '대충 만든 앱'처럼 보여서 바꿨다. 방향 시안은 Gemini 이미지 모델로 두 갈래를 만들어 보고 골랐다(시안 이미지는 저장소에 넣지 않음).

## 저장
- 모두 이 기기 안(IndexedDB, 아이디만 localStorage). 서버로 보내는 것 없음.
- 처음 시작할 때 브라우저에 영구 보관을 요청(`navigator.storage.persist`). 설정에서 크기 확인·전부 지우기.

두 가지로 낸다. 화면·분석 코드는 같다.

| 업데이트 | 스토어에 새 버전 | 사이트에 올리면 다음에 열 때 |

### 안드로이드 앱 (Capacitor 8.5.3)
- `android/`: Capacitor가 만든 프로젝트. 직접 쓴 것은 `MainActivity.java`(작업 예약)와 `AnalyzeWorker.java`(백그라운드 분석)뿐.
- 화면 없는 WebView도 주소를 앱과 같은 `https://localhost`로 맞춰, 같은 IndexedDB에 장면을 쌓는다. 다음에 앱을 열면 홈에 "앱을 닫아 둔 동안 N개 만들어 뒀어요".
- 빌드: `npm ci && npm run apk` → `android/app/build/outputs/apk/debug/app-debug.apk` (JDK 21, Android SDK 36 필요).
- 릴리스: GitHub Actions(`android`)가 main 푸시마다 서명된 APK·AAB를 아티팩트로 올리고, `v*` 태그나 수동 실행(release 입력)이면 GitHub 릴리스로 낸다.
- 서명 키: 다른 앱과 같은 업로드 키. `genshin-checkin` 저장소의 `copy-secrets` 워크플로를 대상 `lesumein/chess-replay`로 수동 실행하면 시크릿 4개(`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`)가 들어온다.
- 앱 아이콘·시작 화면: `node scripts/make-icons.cjs` (`icons/icon.svg`에서 만든다). 짙은 녹색 바탕에 2×2 칸과 되감기 화살표. 녹색은 앱의 대표색(주 버튼, 작은 제목, 지금 수 표시)으로도 쓴다. 먹색 바탕에 4×4 판을 넣은 안(v0.2.2)은 색이 많고 작게 보면 자글자글해서 되돌렸다.
- 플레이 스토어에 올리려면: 개발자 계정, 위 AAB, 개인정보처리방침 페이지(수집 없음이라도 필요).
- 백그라운드 분석은 에뮬레이터 없이 만들어서 아직 실제 폰에서 확인하지 못했다.

### 웹
- GitHub Pages + PWA(`manifest.webmanifest`, `sw.js`). 앱 파일과 Stockfish(7MB)는 기기에 담아 두어 인터넷 없이도 쌓인 장면을 둘 수 있다.
- `sw.js`: 화면·코드는 인터넷이 되면 늘 새로 받고(안 되면 담아 둔 것), Stockfish·판·아이콘은 담아 둔 것을 먼저 쓴다. 새 서비스 워커가 자리 잡으면 두는 중이 아닐 때 한 번 새로 고친다. 파일 목록이 바뀌면 `SHELL`과 `CACHE` 이름을 고친다.

```
node tests/app.test.cjs                    # 아이디 → 분석 → 14수 장면 두기 → 결과 → 홈

node tests/bench.test.cjs                  # 깊이 10, 12, 16
DEPTHS=12,20 node tests/bench.test.cjs
```
Chess.com API는 `tests/fixtures`(내 게임 한 판, 상대 아이디는 지움)로 대신한다.

## 법적으로 확인한 것 (2026-10-26, 법률 자문 아님)
- **Chess.com** (원문: [PubAPI 지원 문서](https://support.chess.com/en/articles/9650547-what-is-the-pubapi-and-how-do-i-use-it), [User Agreement 2026-03-25](https://www.chess.com/legal/user-agreement))
  - PubAPI: "사용자를 괴롭히거나 서비스를 해치거나 기능·IP를 베끼지 않으면" 사용 가능. 병렬 요청 피하기(앱은 한 번에 하나씩).
  - 기보(UGA, 4.C): "공개되어 있고 누구나 어떤 목적으로든 접근·사용·수익화할 수 있다". 그런데 4.D의 이용 허락은 상업적 이용·데이터 수집 도구·다운로드를 "명시적으로 허락한 경우를 빼고" 제외한다. PubAPI가 그 허락 통로로 보이지만 상업 이용 범위는 적혀 있지 않다.
  - AI·자동 접근 제한(4.D, 2026-03 추가): 자동 도구로 콘텐츠에 접근해 "경쟁 제품·서비스", 예시로 "교육 도구"를 만들거나 개선하는 것은 사전 서면 허락이 필요하다. 유료 훈련 앱은 여기에 걸릴 여지가 있다.
  - 정리: 무료·비상업·자기 게임 복기는 위험이 낮다. **유료 기능을 붙이기 전에 Chess.com의 서면 허락을 받는다**([개발자 커뮤니티 클럽](https://www.chess.com/club/chess-com-developer-community)·비즈니스 문의). 허락이 안 되면 유료 기능은 Lichess·PGN으로 가져온 게임에만 둔다.
  - 같은 방식으로 Chess.com 게임을 가져오는 유료 서비스(예: Chessigma)는 있지만, 허락을 받았는지는 공개된 자료로 알 수 없다. Aimchess는 Chess.com이 인수해 비교 대상이 아니다.
- **Lichess API**: 이용약관이 API를 포함한 서비스를 "개인·상업 목적으로, 자기 앱에서" 쓰는 것을 허용하고 합리적 사용량 제한을 둔다([Terms of Service](https://lichess.org/terms-of-service)). 게임 내보내기는 CORS 허용(브라우저에서 직접). Lichess 데이터베이스는 CC0로 배포된다.
- **공정한 플레이**: 진행 중인 게임은 분석하지 않는다(Chess.com 아카이브는 끝난 게임만, Lichess·PGN은 결과가 `*`면 거절). 엔진 분석은 끝난 게임의 복기에만 쓴다.
- **기보 자체**: 수순은 사실 정보라 저작권 대상이 아니라고 보는 것이 일반적. 남의 기보도 공개된 것을 기기 안에서만 다룬다.
- **Stockfish (GPL v3)**: 앱에 함께 넣어 배포하므로 GPL 조건을 지킨다: 수정 없이 넣고, 라이선스 전문 포함, 앱 화면에 소스 위치 표시, 이 저장소(Apache 2.0, GPL v3와 함께 쓸 수 있음)도 공개 유지. 엔진은 Web Worker로 따로 돌고 UCI 메시지로만 주고받는다. 소스를 닫거나 유료로 팔 때는 다시 검토.
- **기물 그림 (CC BY-SA 3.0)**: 출처·라이선스 표시(설정 화면). 그림을 고쳐 쓰면 그 그림은 같은 라이선스로.
- **개인정보**: 개발자가 받는 정보 없음(모두 기기 안). 플레이 스토어에는 개인정보처리방침 페이지와 데이터 보안 양식("수집 없음")이 필요.
